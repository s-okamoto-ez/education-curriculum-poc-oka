# コマンド早見表（チートシート）

`README.md` と演習(Issue)に出てくるコマンドの一覧です。意味を忘れたら、まずここを見てください。本文で概念から説明しているものは「詳しい説明」に章名を書いています。それ以外は、このチートシートの説明が全てです。

## リポジトリを手元に置く

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git clone <URL>` | リモートリポジトリの内容を、まるごと自分のパソコンにコピーする | 本文「演習を始める前に」 |

## 状態を見る（何も変更しない、安全なコマンド）

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git status` | 今どのファイルが変更されていて、それがどこ（ワークツリー/インデックス/リポジトリ）にあるかを表示する | 本文「はじめの一歩」 |
| `git diff` | 変更の中身（何行目がどう変わったか）を表示する | 本文「はじめの一歩」 |
| `git log` | これまでのコミットの履歴を表示する | 本文「記録を振り返る」 |
| `git branch` | 今存在するブランチの一覧と、自分が今いるブランチを表示する | このチートシートのみ |

## 変更を記録する

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git add <ファイル>` | ワークツリーの変更を、インデックス（ステージ）に置く | 本文「変更を記録してみる」 |
| `git commit -m "メッセージ"` | インデックスに置いたものを、1つの区切り（コミット）としてリポジトリに記録する | 本文「変更を記録してみる」 |

## 作業を分ける・共有する

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git switch -c <ブランチ名>` | 新しいブランチを作って、そこに移動する | このチートシートのみ |
| `git switch <ブランチ名>` | 指定したブランチに移動する | このチートシートのみ |
| `git push` | ローカルの記録をリモートに送る | 本文「全体像」 |

**ブランチとは**: 作業を「本流(`main`)」から分けて、独立した場所で進められるようにする仕組みです。分けておけば、複数人が同時に作業していても、お互いの変更を汚しません。作業が終わったら、GitHub上で **Pull Request（PR）** を出し、「この変更を`main`に取り込んでほしい」と提案します。


## マージする・コンフリクトを解決する

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git merge <ブランチ名>` | 指定したブランチの変更を、今いるブランチに取り込む | 演習04 |
| `git log --oneline --graph --all` | 全ブランチの分岐・合流を、簡潔な図で見る | 演習04 |
| `git merge --abort` | マージを取りやめて、始める前の状態に戻す | このチートシートのみ |

**コンフリクトの印**: `<<<<<<<` から `=======` までが自分側、`=======` から `>>>>>>>` までが相手側です。印を全部消してから `add` → `commit` します。

## 過去を調べる

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git log <ファイル>` | そのファイルの変更履歴だけを見る | 本文「過去を調べる」 |
| `git log -p <ファイル>` | 履歴に、変更の中身(diff)も添えて見る | 本文「過去を調べる」 |
| `git blame <ファイル>` | 各行を最後に変えたコミットを、1行ずつ表示する | 本文「過去を調べる」 |
| `git show <コミット>` | 指定したコミットで、実際に何が変わったかを見る | 本文「過去を調べる」 |

## 取り消す

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `git revert <コミット>` | そのコミットの変更を打ち消す、**新しいコミットを追加する** | 演習05 |
| `git restore <ファイル>` | まだコミットしていない変更を、直前の状態に戻す | このチートシートのみ |

> [!IMPORTANT]
> **`git revert` は、コミットを「消す」のではなく「打ち消す新しいコミットを足す」操作です。** 履歴は残るので、他の人と共有した後のコミットを取り消すときも安全です。**「見つけたコミットを機械的にrevertする」のではなく、その変更の意図まで理解してから判断してください**(演習05)。

## 追跡から外す

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `.gitignore`(ファイル) | ここに書いたパターンに一致するファイルは、これから先 `git add` の対象にしない | 演習06 |
| `git rm -r --cached <パス>` | ファイル自体は手元に残したまま、**すでに追跡しているものだけ**Gitの追跡から外す | 演習06 |

> [!IMPORTANT]
> **`.gitignore` は「これから追跡し始めないでください」という指示で、すでに追跡中のファイルには効きません。** 一度 `add` してしまったファイルを外すには `git rm --cached` が必要です(演習06)。

# コマンド早見表（チートシート）

`README.md` と演習(Issue)に出てくるコマンド・用語の一覧です。意味を忘れたら、まずここを見てください。本文で概念から説明しているものは「詳しい説明」に章名を書いています。それ以外は、このチートシートの説明が全てです。

## リクエストを送る

| コマンド | やること | 詳しい説明 |
|---|---|---|
| `curl -v <URL>` | 名前解決や接続先など、通信の様子を詳しく表示しながらリクエストを送る | 本文「はじめの一歩」 |
| `curl <URL>` | 指定したURLにGETリクエストを送り、レスポンスのボディを表示する | 本文「はじめの一歩」 |
| `curl -I <URL>` | ボディは取得せず、ステータスコードとヘッダだけを表示する | 本文「はじめの一歩」 |
| `curl -X POST <URL> -d "キー=値"` | 指定したURLにPOSTでデータを送る | 本文「はじめの一歩」 |
| `curl -D - <URL>` | ヘッダを表示しながら送る(本文も表示される) | 演習04 |
| `curl -D - -o /dev/null <URL>` | ヘッダだけ表示し、本文は捨てる | 演習04 |
| `curl -H "ヘッダ名: 値" <URL>` | 独自のヘッダを付けて送る(認証などに使う) | 演習04 |
| `curl -L <URL>` | リダイレクト(3xx)されたら、`Location` の行き先へ自動で追いかける | 演習06 |

## ローカルサーバーを動かす(演習04〜11)

| コマンド | やること |
|---|---|

## 用語

| 用語 | 意味 | 詳しい説明 |
|---|---|---|
| ホスト名 | `example.com` のような、人間向けの相手の名前 | 本文「URLの中身」 |
| IPアドレス | コンピュータが実際に通信で使う、数字の住所 | 本文「URLの中身」 |
| DNS | ホスト名をIPアドレスに変換する仕組み(電話帳のようなもの) | 本文「URLの中身」 |
| ポート番号 | IPアドレスの中の、どの窓口宛てかを表す番号(HTTPは80、HTTPSは443) | 本文「URLの中身」 |
| リクエスト / レスポンス | クライアントの「お願い」と、サーバーの「返事」 | 本文「HTTPとは」 |
| メソッド | リクエストの「何をしてほしいか」を表す部分(GET, POSTなど) | 本文「リクエストの中身」 |
| ステータスコード | レスポンスの結果を表す3桁の数字(200, 404など) | 本文「レスポンスの中身」 |
| ヘッダ | リクエスト・レスポンスに付く補足情報(伝票のようなもの) | 本文「ヘッダ」 |
| ボディ | 実際のデータ本体 | 本文「レスポンスの中身」 |
| `Authorization` ヘッダ | 「私はこういう者です」という証明を運ぶヘッダ | 本文「認証」 |
| `Cache-Control` ヘッダ | この結果を一時保存(キャッシュ)してよいかを伝えるヘッダ。`no-store` は「保存しないで」の意味 | 演習09 |
| オリジン | `http://` + ホスト名 + ポート番号の組み合わせ。1つでも違えば別オリジン | 演習10 |
| CORS | 別オリジンへのリクエスト結果を、ブラウザが読み取ってよいかを制御する仕組み | 演習10 |
| `Access-Control-Allow-Origin` ヘッダ | このレスポンスをどのオリジンに渡してよいかを、サーバー側が明示するヘッダ | 演習10 |

**代表的なステータスコード**: このチートシートのみで説明します。

| コード | 意味 |
|---|---|
| 200 | 成功 |
| 301 | 恒久的に別の場所へ引っ越した | 
| 302 | 今回だけ別の場所へ案内する | 
| 401 | 未ログイン。あなたが誰か分からない | 
| 403 | ログイン済みだが、権限が無い |
| 404 | 指定した場所が見つからない |
| 500 | サーバー側の処理でエラーが起きた |

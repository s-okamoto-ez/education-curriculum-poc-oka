# 入門フェーズ タスク一覧

入門の教材について、2027年4月の開講までにやることを単元ごとにまとめた一覧です。単元ごとに「前後の段階とのつながり → 目的 → 到達目標と今ある教材 → だから必要なタスク」の順に書いてあります。担当の割り振りはこの一覧を見て決めます(担当はここに書きません)。

> [!IMPORTANT]
> **初めて読む人は、先に [カリキュラムの全体像](https://github.com/ezorise-labs/education-ai-engineer-wayfinder/blob/main/.scratch/new-engineer-education/curriculum-overview.md) を読んでください。**入門が研修全体の中で何を担っているかが分かります。教材の作り方の決まりは [制作ガイド](production-guide.md) にあります。

> [!NOTE]
> **タスクの取り方と進み具合は Issue で管理しています。**[「教材づくり」ラベルの Issue 一覧](https://github.com/ezorise-labs/education-curriculum-poc/issues?q=is%3Aissue+label%3A%E6%95%99%E6%9D%90%E3%81%A5%E3%81%8F%E3%82%8A) から、手が空いた人が取っていきます。この一覧は、各タスクの説明と完了条件を確かめるための資料です。

## 読み方

各章のタスクは、まず短い一覧表で全体を見渡せるようにし、その下の「各タスクの中身と完了条件」(折りたたみ可)に1つずつの説明を書いています。

一覧表の列は次のとおりです。

| 列 | 意味 |
|---|---|
| ID | タスクの識別子。依存関係を示すときに使う(`I-` は入門) |
| タスク | 何を作る・するか |
| 埋める穴 | 到達目標の表のどの不足を埋めるタスクか |
| 目安 | 作業時間の目安。[教材の残り工数の見積もり](https://github.com/ezorise-labs/education-ai-engineer-wayfinder/blob/main/.scratch/new-engineer-education/issues/31-material-effort-estimate.md) の総量を割ったもので、根拠は薄い。実績が出たら直す |
| 時期 | いつまでに終えたいか |
| やれる人 | 誰でも = 誰がやってもよい / 教える講師 = 入門を教える講師本人でなければならない(自己検証は、作った人ではなく教える人が行う決まり) |

各タスクの中身には、説明のほかに「完了条件」(これを満たせば終わり)と「先に要るもの」(先に終わっている必要があるタスク)を書いています。

- 締切は2027年1月末。2〜3月は修正と教える準備に充てる
- 教材の生成はClaude Codeに任せてよい
- 教材の不具合を見つけたら、このリポジトリにIssueを立てる

## 入門の全体像

入門の目的は、**本編のコードベースを自分で立ち上げられ、どのファイルが何を担当しているかを追え、エラーがどこで起きているかを切り分けられるようにすること**です。7つの単元は、現場でいちばん多い問い合わせ「画面のこの数字がおかしい」を調べる道筋(画面 → 通信 → サーバーのコード → SQL → データベース)に沿って並んでいます。

入門の時間は約108時間・6単元から、約120時間・7単元に変わりました。今ある演習の量と、新しい枠を比べると次のとおりです(2026-09-25時点。演習の目安時間の合計で、どちらも未実測)。

|---|---|---|---|---|
| 1 | コマンドライン基礎 | 6h | 6本・2.7〜3.8h | 時間 |
| 2 | Git基礎 | 10h | 6本・3.0〜4.4h | 時間。プルリクエストが発展扱い |
| 3 | HTML/CSS基礎 | 20h | 12本・10.9〜15.7h | 時間 |
| 4 | プログラミング基礎 | 50h | 16本・25.5〜33.5h | 空のファイルから書く経験、非同期、DOM操作、時間 |
| 5 | HTTP基礎 | 8h | 11本・5.4〜7.6h | ほぼ足りている |
| 6 | SQL基礎 | 10h | 6本・4.8〜6.9h | 時間 |
| 7 | つなぐ | 約10h | なし | 単元そのもの |

**「時間」の不足を演習を足して埋めるかは、まだ決めていません。**目安時間がどれも未実測なので、12月末の試行の実測を見て決めます(8章I-81)。

## 1. コマンドライン基礎(6h)

#### 前後とのつながり
最初の単元です。ここで覚える操作は、このあとのすべての単元で使います。本編では、システムを立ち上げるとき、ログを調べるときに使います。演習6の環境変数(`$PATH`)は、「つなぐ」単元でデータベースの接続先(`DATABASE_URL`)を設定するときの下地です。

#### 目的
黒い画面で、今どこにいるかを把握し、ファイルを探せるようにします。GUIで1時間かかる作業が1行で終わる場面があることも見せます。

#### 到達目標と今ある教材

| 到達目標 | 今ある演習 | 足りているか |
|---|---|---|
| 今いるフォルダを確かめ、別のフォルダへ移動できる | 1今どこにいるかを知る、2ファイルを作って中身を見る | 足りている |
| 大量の出力やファイルから、必要な行だけを絞り込める | 3パイプでつないで絞り込む、5ワイルドカードとfindで探る | 足りている |
| ファイルの権限と環境変数の中身を確かめられる | 4権限を読む、6なぜgitは動くのにこのツールは動かないのか | 足りている |

時間は、今ある演習6本で2.7〜3.8hです。新しい枠の6hより2〜3h少なく、演習を足すかはI-81で決めます。

## 2. Git基礎(10h)

#### 前後とのつながり
コマンドライン基礎の次の単元です。本編では、課題の提出とレビューがすべてプルリクエストで行われます。後半のチーム課題では、共有リポジトリでコンフリクトが起きます。演習5の履歴調べ(`git blame`)は、本編で「由来の分からないコード」の経緯を調べるときにそのまま使います。

#### 目的
変更を記録し、履歴をたどり、プルリクエストで共有できるようにします。Gitは挙動が目に見えないので、概念を先に説明してから演習に入ります。

#### 到達目標と今ある教材

| 到達目標 | 今ある演習 | 足りているか |
|---|---|---|
| どのファイルを変えたかを確かめ、変更を記録できる | 1 status/diffを読む、2はじめてのコミット | 足りている |
| ブランチを切り、コンフリクトを自分で解決できる | 3ブランチを切る、4コンフリクトを起こして解決する | 足りている |
| 履歴から原因を調べられる | 5過去の履歴から原因を突き止める | 足りている |
| Gitで管理すべきでないファイルを、管理から外せる | 6 .gitignoreを設計する | 足りている |
| プルリクエストを出し、レビューの指摘に対応できる | 3の発展課題でプルリクエストを作るだけ | 必修になっていない(本編の前提なので要判断。I-82) |

時間は、今ある演習6本で3.0〜4.4hです。新しい枠の10hより6〜7h少なく、演習を足すかはI-81で決めます。

## 4. プログラミング基礎(34h → 50h)

#### 前後とのつながり
画面の見た目(HTML/CSS)の次に、画面を動かすロジックに入ります。ここで扱う素のDOM操作は、本編でReactを読むための下地です(素のDOMを知らないと、Reactが何を解決しているのか分かりません)。非同期は、「つなぐ」単元でデータベースに問い合わせるときに実物で使います。本編で最初に任される課題(難易度1)は、条件分岐を1つ直す程度の修正を自分で書けないと進められません。

#### 目的
コードを追って結果を予測でき、エラーを読んで直せ、小さな修正を自分で書けるようにします。言語はTypeScriptで、JavaScriptは経由しません。

#### 到達目標と今ある教材

| 到達目標 | 今ある演習 | 足りているか |
|---|---|---|
| コードを追って、実行結果を予測できる | 1出力を予測する、7引き継いだコードベースを読む | 足りている |
| エラーメッセージと型エラーを読んで、自分で直せる | 2型に怒られる、3エラーを頼りに直す、9型は最初から警告していた | 足りている |
| 数十行の関数や条件分岐を自分で書き足せる | 4配列を操作する、10新しいコマンドを足す、11〜13(既存コードの修正) | 既存コードへの書き足しはあるが、空のファイルから書く経験がない |
| 非同期の処理が、どの順番で何をしているかを読み取れる | 5非同期処理を読む(60〜90分の1本だけ) | 薄い。図解もない |
| 画面の要素を直接書き換えるコード(素のDOM操作)を読める | なし(READMEに説明があるだけ) | 演習がない |

時間は、今ある演習16本で25.5〜33.5hです。新しい枠の50hより16〜24h少なくなっています。

演習14〜16(壊しにいく、回帰確認の仕組みを作る、引き継ぐ)は、上の目標とは別に、本編で必要になる「確かめる」「伝える」の練習として残します。
